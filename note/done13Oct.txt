# BuyNest — Feature 2: Product Ratings and Reviews System

## Objective

Implement a complete product ratings and reviews feature similar to major ecommerce platforms.

Customers should be able to view product ratings, submit reviews, and identify verified purchases.

Admins should be able to moderate reviews, manage review settings, and add clearly labeled manually entered or imported reviews.

## 1. Product ratings

Implement:

- 1 to 5 star ratings
- Average product rating
- Total rating count
- 5-star distribution summary
- Customer reviews list
- Sorting by recent, highest rating, and lowest rating
- Pagination for reviews

Ensure product ratings are calculated using eligible published reviews.

## 2. Customer reviews

Allow authenticated users to:

- Submit a star rating
- Add a review title
- Write review content
- View their submitted reviews
- Edit or delete their own reviews within configured policy limits

Support guest reviews only if a secure verification and anti-abuse mechanism is available.

## 3. Verified purchase detection

Automatically determine verified-purchase status from backend order records.

A review should receive Verified Purchase status only when the review is linked to an authentic eligible purchase of that product.

Use the existing order lifecycle to determine purchase eligibility.

Do not let customers or admins arbitrarily assign verified-purchase status.

Prevent forged purchase references or review ownership.

## 4. Admin reviews management

Create a Reviews Management section with:

- All reviews table
- Product name
- Customer/reviewer name
- Rating
- Review text
- Verified/Unverified/Imported origin indicator
- Moderation status
- Created date
- Approve/Reject actions
- Hide/Restore actions where appropriate
- Search and filters
- Pagination

Allow admins to enter reviews manually only when clearly identified as admin-entered/imported content.

Do not fabricate customer identities or falsely represent manually entered reviews as genuine verified purchases.

## 5. Admin configuration

Create Review Settings:

- Enable/Disable Product Reviews
- Allow Reviews from Verified Purchasers Only
- Require Admin Approval
- Allow Review Editing
- Review eligibility rules
- Maximum review content length

Enforce all relevant settings on the backend.

## 6. Mobile UI

Implement:

- Rating summary on product details
- Review list
- Star rating input
- Write review screen
- Review submission feedback
- Empty reviews state
- Error and loading states
- Verified purchase badges
- Review moderation status where relevant

Follow existing BuyNest design patterns.

## 7. Database and backend

Inspect the existing Prisma schema and introduce only the necessary models and fields.

Implement:

- Review ownership
- Product relationships
- Purchase verification references
- Moderation statuses
- Review origin tracking
- Duplicate review prevention
- Safe rating aggregation

Protect all review APIs with appropriate validation and authorization.

## 8. Testing

Test:

- Review submission
- Review editing/deletion
- Verified purchase eligibility
- Unverified reviews
- Admin-entered review labeling
- Unauthorized modification
- Duplicate reviews
- Moderation workflow
- Rating averages and counts
- Review feature disabled behavior

## Restrictions

Do not alter existing orders or purchase history.

Do not create fake verified purchases.

Do not modify production records.

Do not apply production migrations.

Preserve existing uncommitted changes.

## Expected result

A fully working, secure reviews system for mobile customers and admins, including truthful verified-purchase identification and admin moderation.

Run relevant tests and report all changes.

# BuyNest — Task 4: Implement Minimal Return and Refund Management

## Problem

BuyNest supports order cancellation but does not currently implement a completed-order return and refund workflow.

## Objective

Implement a simple, reliable, admin-managed return/refund process suitable for a local Cash-on-Delivery ecommerce store.

## Instructions

1. Inspect the existing order statuses, refund enums, order lifecycle, payment collection tracking, inventory audit records, admin APIs, and admin UI.
2. Determine whether any existing return/refund infrastructure can be safely reused.
3. Propose the smallest complete V1 workflow before editing.
4. Support recording a return or refund request against an eligible delivered order.
5. Allow authorized admins to review, approve, reject, and mark refunds as completed.
6. Support clear recording of full or partial refunds where consistent with the existing architecture.
7. Track refund amount, reason, status, timestamps, and authorized admin actions.
8. Prevent duplicate refund processing and amounts exceeding the eligible collected amount.
9. Ensure cash collection and refund records can be reconciled.
10. Do not automatically restore inventory for returned goods until their physical condition and restocking eligibility are confirmed.
11. Preserve existing cancellation and order status functionality.
12. Add relevant validation, authorization, and regression tests.

## Restrictions

- This is a Cash-on-Delivery V1 application.
- Do not integrate online payment gateways.
- Do not introduce unnecessary complex reverse logistics.
- Do not modify live orders or production database records.
- Create Prisma migrations only if necessary and do not apply them to production.
- Do not implement changes to the completed-order lifecycle that interfere with existing fulfillment history.

## Expected Result

Store administrators can record, track, and reconcile manual COD returns and refunds safely.

Provide modified files, workflow documentation, database migration requirements, and test results.
